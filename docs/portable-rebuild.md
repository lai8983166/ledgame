# 重新打包时保留已有数据

日常使用 `pnpm portable:dist` 生成目录版和 ZIP。`portable:dir` 只更新目录版，`portable:zip` 同时更新目录版和 ZIP。三个命令均通过 `scripts/portable-rebuild.cjs`，不要直接对已有发行目录运行 electron-builder。

每次构建都将两个入口放在同一发行目录；ZIP 也包含这两个文件。

| 入口 | Windows 文件图标 | 启动行为 |
| --- | --- | --- |
| `LED Game.exe` | 彩色方块 | 打开原有管理界面 |
| `LED Game Play.exe` | 霓虹游戏人物 | 授权与初始化完成后直接打开全屏游戏界面，按原流程选择游戏 |

两个入口共用该目录的数据库、设置、媒体和后台服务。请将两个 EXE 和其它发行文件一起保留在解压目录。EXE 文件图标在打包时写入，配置 Tab 的应用图标仍按该包已有配置加载。
本机需要激活时，游戏入口会先显示原有激活窗口。全屏游戏沿用配置中的退出密码，退出后返回管理界面。

开始前保存编辑内容并关闭 `release/win-unpacked` 中的游戏端及其后台服务。入口会检查该目录内运行的 EXE 和 Java 进程；仍在运行时停止打包，不复制活跃数据库，也不强制结束用户进程。

重新打包默认保留旧发行包的以下内容：

| 位置 | 内容 | 新目录版 | 新 ZIP |
| --- | --- | --- | --- |
| `data/database` | 游戏、关卡、精灵、游戏内配置及数据库备份 | 保留 | 包含 |
| `data/settings` | 配置 Tab 和语言 | 保留 | 包含 |
| `data/branding` | 图标、副屏背景及待机媒体副本 | 保留 | 包含 |
| `resources/media` | 游戏媒体库 | 保留 | 包含 |
| `elc408` | 控制器及接线配置 | 保留 | 包含 |
| 其它已有 `data` 内容 | 旧授权文件、日志和 Chromium 会话缓存 | 原位保留 | 不包含 |

已有媒体和控制器目录为准，包括用户删除文件后留下的空目录；不会将默认媒体或默认控制器文件补回。没有旧发行包时，仍使用项目既有种子数据库、媒体来源及默认配置首次构建。

入口先将旧 `data`、媒体和控制器目录完整备份至 `.build/portable-rebuild-*/snapshot`，记录 SHA-256 清单，然后构建至同一工作目录的 `output`。新 ZIP 从持久数据白名单生成，不包含授权、日志或会话缓存。机器授权的存储和迁移规则见 `portable-data.md`。

新目录版的完整性和保留文件校验通过后，再次确认旧包没有启动且文件内容未变化，才发布程序文件和 ZIP。已有 `data` 原位保留，避免打包器清理其内容。构建失败不会清理旧发行目录；发布中断时，快照和已校验构建仍保留在工作目录，可用于恢复数据或重新完成发布。

每次构建的 `snapshot-manifest.json` 和 `result.json` 保留在工作目录，命令输出会显示具体路径。若进程异常终止留下 `release/.portable-rebuild.lock`，先确认没有进行中的打包任务，再移除该锁后重试。

直接调用 electron-builder 仍是底层构建命令，不具备这里的数据保留流程。
